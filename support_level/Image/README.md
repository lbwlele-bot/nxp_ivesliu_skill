# Image

这里放已经下载或验证过、可直接用于烧写和对比的镜像资产。

这一层首先回答：

- 当前本地是否已有目标 SoC、板型和软件版本对应的镜像
- 哪个目录是本次烧写、启动对比或问题复现的输入基线
- 镜像是完整发布包、解包目录，还是 case 生成的单独产物

## 当前本地镜像入口

当前本地可以看到这些基线：

- `i.MX8DXL-6.18.2-1.0.0/`
- `LF_v6.6.52-2.2.0_images_IMX93EVK/`
- `Real-time_Edge_v3.4_IMX943-19X19-LPDDR4-EVK/`
- `Real-time_Edge_v3.3_IMX95-19X19-LPDDR5-EVK/`

其中部分发布包同时保留了解包目录和原始压缩包。
Git 只保存这份入口说明，不保存镜像、rootfs、压缩包和其它二进制本体。
具体文件是否存在、大小与校验值是否正确，仍以当前本地目录和当前 case 证据为准。

## 使用规则

1. 先确认 SoC、silicon revision、板 revision、DDR 和软件版本。
2. 优先复用身份完全匹配的现成镜像，不因文件名相似跨板型复用。
3. 烧写前进入 `board-exec`，重新确认连接、boot mode、目标存储和串口观察链路。
4. `uuu` 或其它传输命令成功，只证明传输动作完成，不自动证明 U-Boot、Linux 或业务负载已经运行。
5. case 自己编译生成的镜像保留在 `work/<case>/artifacts/`，不要反向覆盖这里的共享基线。

## 与其它目录的边界

- 固定 DDR、ELE、AHAB 等输入在 `../firmware/`。
- 需要重新编译产物时进入 `../compile_targets/` 和对应源码项目。
- 真实板烧写、复位和启动判断由 `board-exec` 负责。
- 当前任务的日志、产物和验证证据放在 `../work/<case>/`。
