# 教学复盘与审查场景

用于教师审查自己的出题、能力归因和工具修复；不是学生的解题输入。
以下是工程场景和判断方式，不是能力分级或固定轮次数量。

## 2026-11 教学中的可复用教训

来源：DS 的 `support_level/work/2026-11-02-imx943-imx8mp-1250-engineering-training/`。
轮次仅供本机回查；本 skill 的使用不依赖这些未上传的日志。

| 观察 | 教师需要改变的做法 |
| --- | --- |
| 早期重建系统时大量读旧变体，超时且回答过长 | 将问题收敛到当前未解决步骤，让学生给出证据和下一步，避免要求完整历史复述 |
| Round 4 和 Round 51 都撞到同会话 identity 前置 | 教师发题前核对工具全局门与动作内部前置；不能只修当轮 prompt 后忘记同类问题 |
| 多轮 prompt 明确规定两个 MCP 操作及顺序 | 这是指导下执行，不能写成独立规划；稳定后改为目标级任务验收 |
| 学生正确停在旧 reset marker | 保留拒绝证据，由教师审查历史事务后决定有限重试；不奖励无止境停等 |
| Round 49 的修复题已给出真实 receipt 耦合的根因 | 学生完成了给定诊断后的实现；缺陷首先由教师回归发现 |
| Round 53 学生在 final 解释了 recipe 字面量差异，Round 54 又收到具体修改要求 | 独立定位、教师指定方案、学生实现应分别归因 |
| mock 用简化 SDPS 行，实际 UUU 输出含超时修饰符 | 以实际版本的只读输出构建夹具，再补语义反例；不盲目放宽匹配 |
| 收据已经生成，但手册/入口仍写“当前缺收据” | 通用说明写条件，实时事实交给 case；维护一个容易找到的当前状态 |
| 每条操作新开会话，教师反复审计、解释下一条操作 | 保留动作证据边界，在同一授权工作单元内连贯推进；新会话用于真正的迁移或恢复验收 |
| 缓冲运行器等待期间，教师宣称学生正在扩充测试 | 等待时间不能证明活动内容；只报告可见事件、审计或无增量输出 |

该阶段实际完成了从精确产物 RAM boot、SD bootloader 写入到复位后 U-Boot 的
物理链路。多数步骤由教师明确排序，工具完成身份/哈希/阶段门控，因此结论应是：
“在教师限定步骤和固定工具下完成部署与证据解释；目标级自主规划尚待验证。”
这是对能力归因的修正，不撤销已有的板级原始证据。

## 发题示例

正常工程任务可以这样给：

> 继续当前 case，核对板子和产物，完成已授权的 bootloader 部署并验证启动
> 阶段。目标版本和可写介质以 case 的确认记录为准，文件系统不在写入范围。
> 按工作区规则自行选择步骤，遇到不满足的前提先定位，留下可恢复状态和证据。

教师另行核对授权、工具能力和验收标准；不要把选中的命令、预期 USB 行或最终
故障原因写进该题。若目标仅是检查一个 consumer 契约，可以明确给固定操作，
但在记录中写清这一点。

## 教师修订 skill 后的场景检查

这些场景可用于桌面审查；真实学生验收仍需实际新会话证据。

| 给定情况 | 合理行为与不应推出的结论 |
| --- | --- |
| 用户只说“继续”，先前已经授权复位与限定介质写入 | 从当前记录恢复授权与状态，在范围内推进；不每轮索取相同许可 |
| 只允许 consumer 操作，但工具要求同会话 identity | 修教师授权范围，保留正确拒绝；不移除工具身份门 |
| real receipt 已存在，离线 negative test 失败 | 临时 case 构造缺失场景，保留真实 receipt；测试通过不等于实机结果 |
| 学生修改了生产 parser 和自己的 tests，并报告全通过 | 教师用原失败输入和独立语义反例复核，检查未识别行的默认分支；不只复跑同一批测试 |
| student 在带指定步骤的新会话中成功 | 记录指导下执行及学生自己的证据判断；另用正常目标请求检查规划与恢复 |
| 新会话读当前 case 并正确续接 | 这是正常的持久化能力；禁止的是教师答案泄漏，不是正常工程记录 |
| 新会话面对已有 completed receipt | 刷新物理状态并判断有效性，再决定续接或恢复；不为了重测而直接重复刷写 |
| user 提供不同版本的可用系统，任务将覆盖其 bootloader | 在已有授权内说明版本影响、记录基线与恢复路径，阶段完成后明确板子留下的状态 |
| handoff 是旧 BLOCKED，receipt/ledger 有新证据 | 原 owner 更新或显式指向后继状态；保留历史但解决当前入口矛盾 |
| 子进程迟迟无 stdout，runner 只在结束保存 JSONL | 查看能获取的审计/进程，否则明确无可见进展；不把等待推断成正在测试或板子未变 |

## 工具修复的复核重点

对安全相关解析器，教师的反例应来自语义边界：缺项、多个对象、串行拼接、
未识别可执行行、合法格式变化、错误目标及动作顺序。不要只给学生代码里已有
分支各写一个镜像测试，也不要把“未知行被忽略”表述为“未知行全被拒绝”。

所需硬件不可用时，验证离线契约并把物理结论留空即可。代码通过回归、学生能
执行固定操作、学生能自主完成工程任务是不同事实，汇报时逐一写明证据来源。
